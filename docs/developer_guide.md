# Developer Guide

## Stack

- Python
- FastAPI
- PostgreSQL
- SQLAlchemy ORM
- Alembic
- Jinja2
- HTML/CSS/Vanilla JavaScript
- optional local `llama.cpp` OpenAI-compatible HTTP endpoint
- signed cookie sessions for role-based accounts

## Install

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

## Configure `.env`

Minimum database configuration:

```env
SECRET_KEY=change-me-for-local-development
DATABASE_URL=postgresql+psycopg://adresponse:adresponse@localhost:5432/adresponse
USE_LLAMA=false
```

The app must use PostgreSQL. SQLite is used only in isolated unit tests for helper functions.

## Migrations

```bash
alembic upgrade head
```

To create a new migration after model changes:

```bash
alembic revision --autogenerate -m "description"
```

Review autogenerated migrations before applying them.

## Seed data

```bash
python3 -m app.db.seed
```

Seed data creates initial categories, prepared comments and demo users:

- `admin` / `admin123`
- `manager` / `manager123`
- `client` / `client123`

## Run

```bash
uvicorn app.main:app --reload
```

## Tests

```bash
pytest
python3 -m compileall app tests alembic
```

Current tests cover:

- request classification;
- sentiment analysis;
- knowledge base comment selection;
- prompt builder;
- local fallback generation;
- llama.cpp fallback behavior without a real server;
- admin helper validation;
- manager workflow helpers: grouping, finish appeal, client resolution for report upload;
- appeal rating aggregation;
- AI answer feedback validation;
- admin analytics helper logic;
- unusual-question fallback behavior;
- page smoke checks.
- password hashing and role helper checks.

## Architecture

Main directories:

- `app/routers/` - FastAPI routes.
- `app/services/` - local NLP, response generation, prompt building, workflow logic.
- `app/models/` - SQLAlchemy ORM models.
- `app/db/` - session, metadata, seed data.
- `app/templates/` - Jinja2 pages.
- `app/static/` - local CSS and JavaScript.
- `app/llama/` - local llama.cpp HTTP adapter.

## Authentication

The project uses signed cookie sessions through Starlette `SessionMiddleware`. Passwords are stored as PBKDF2 hashes generated by `app/core/security.py`; plain text passwords are never stored. Route helpers in `app/core/auth.py` provide current user lookup and role checks.

## Safety rules

Do not add external cloud LLM APIs. The only LLM integration must be local `llama.cpp`. The response generator must not invent prices, deadlines, guarantees, services, facts or exact advertising results.

## Feedback and analytics

Migration `20260516_0005_add_feedback_tables.py` adds:

- `appeal_feedback` for the client's final rating of a completed appeal;
- `ai_response_feedback` for like/dislike on system answers and dislike reasons.

Analytics are built in `app/services/analytics.py` and rendered with local HTML/CSS only. Manager workflow helpers live in `app/services/manager_workflow.py`; report upload resolves the client from the appeal conversation session instead of relying on a missing form field.
